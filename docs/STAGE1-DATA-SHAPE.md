## このまとめで使う言葉

- **記録**: アプリが覚える1件のまとまり（1つの版、1本の話題など）。
- **名札**: 記録を見分けるための番号。
- **端末**: PC・スマホなど、アプリを開く機械。
- **クラウド**: Firebase（Google のデータの置き場）。あなたのアカウントだけが読める所に置きます。
- **同期**: 端末とクラウドの中身をそろえること。
- **つなぎ口（コネクタ）**: Claude がアプリに版を足すための入口。段階3で作りました（[CONNECTOR.md](CONNECTOR.md)）。
- **置き場**: クラウドの中の棚。「Claude が読める置き場」と「Claude が読めない置き場」の2つに分けます。
- **指紋**: 記録の中身から計算した短い印。中身が同じなら同じ印になります。
- **書く係・照合の係**: 版を作る時に、記事を読んで話題を書く Claude と、書いた物を元記事と照らし合わせて確かめる、別の Claude。

## なぜ「固める」のか

版と話題は30日で入れ替わりますが、「知ってる」にした用語と用語の辞書はずっと残ります。また、段階3で作るつなぎ口とアプリは、同じ形の記録をやり取りします。名札の付け方や置き場を後から変えると、続報のつながりや「知ってる」が切れたり、Claude に見せない物の守りを作り直したりすることになるので、段階1の前に固めます。

## 全体の絵：誰が何を書くか

| 記録 | 書くのは | 置き場 | いつ消えるか |
|---|---|---|---|
| 版（1回の更新） | Claude | Claude が読める | 30日 |
| 話題（1本ずつ） | Claude | Claude が読める | 30日 |
| 訂正 | Claude | Claude が読める | 30日（元の話題と一緒に） |
| 用語の辞書 | Claude | Claude が読める | 消さない |
| 作れなかった印 | Claude | Claude が読める | 30日 |
| 「知ってる」にした用語 | あなた（アプリ） | Claude が読める | 消さない |
| 既読（と、見た版） | あなた（アプリ） | Claude が読めない | 30日 |

- Claude ができるのは「足す」ことだけです。足した物を直すことも、消すこともできません。アプリも、Claude が足した記録を書き換えず、30日が来たら消すだけです。
- 既読は「あなたが何を読んだか」の記録なので、Claude が読めない置き場に置きます（D21）。保存を作らないのでこの置き場は既読だけですが、分ける作りは残します。Claude に渡すあなたの情報は「知ってる」にした用語だけです。

## すべての記録に共通して覚えること

- 名札と、作った日時（世界共通の時計で覚え、画面に出す時だけ日本時間に直します）。
- 誰が作ったか（Claude か、あなたか）と、どの AI か（今は Claude だけ）。記録の形の版（今はすべて 1）。
- Claude が作った物には、さらに「作ったモデルの名前」（Claude が名乗った物。Fable 以外で動いたかの目安。D7）と「どの回の作業か」（つなぎ口が付けます）。
- あなたが書く物（既読・「知ってる」）には、さらに「最後に変えた日時」。

## 版（1回の更新）

1つの版に1つの記録です。名札は日付と時刻だけで決まります（例: 2026年11月15日の 12:00版。日付は日本時間）。どの時刻の版かは、Claude ではなくつなぎ口が、作業を始めた時刻で決めます（取り違えないように）。1つの時刻に版は1つだけで、出た版を作り直すことはしません。

覚えるのは、日付と 12:00版か20:00版か・話題の並び（知るべき順。ふだんは20本で、30本まで）・候補の数（例: 集めた記事 388件）と選ばなかった主な見出し（20件まで。AI の選び方を後からのぞけるように。6.5。どこに出すかは段階2）・候補を集めた時間の窓・使用量（測れる時だけ）です。

Claude は、話題を全部足し終えてから、最後に版の記録を足します。アプリは版の記録が届いた時に初めてその版を出すので、途中で止まった版は出ません。

## 話題（1本）

1本の話題に1つの記録です。名札は「どの版か」と「中身の指紋」から作ります（例: 2026-11-15-12 と、8字の印）。同じ物を2回送っても1件のままで、Claude が書き直した物は別の名札になるので、やり直しても前の物とぶつかりません。どちらを出すかは、版の記録の並びで決まります。

### 覚えること

| 覚えること | 長さ・数の上限 | 決まりの目安 |
|---|---|---|
| どの版か・順位と短い理由 | 理由 200字まで | |
| 地域 | 国内か世界のどちらか | |
| ジャンル | 政治、経済、テクノロジー、AI、事故・事件、スポーツ、エンタメの、どれか1つ | |
| 重大印 | ある・なし | 1日に0〜3件 |
| 見出し | 60字まで | 30字台 |
| 要約 | 300字まで | 120〜200字（空白を除く） |
| 結論 | 確定・未確定・見通しのどれかと、補足（200字まで）と、速報・未確認の印 | |
| だから何？ | 4つの観点（暮らし・お金、社会の仕組み、世界の力関係、なぜ話題か）。各 800字まで | |
| 当事者の主張 | 15まで。名前 60字・立場（賛成・反対・条件付き・不明）と、その補足 60字・主張 400字・理由 300字 | 政治は議席の多い順 |
| AI の見解と対立見解 | 軸の名前 80字・論点 150字・見解と対立見解は各 800字まで。「対立見解なし」の時は、その印と（あれば）理由 200字 | 分量の差は1割まで |
| 経緯 | 12行まで。1行に「日付」（記事に書かれたまま。無い行もある）と「出来事」（160字まで） | 書いた順に並べる |
| 続報 | 前の話題と、何が新しくなったか（200字まで） | |
| 用語 | 20語まで。表記 40字・別名 10まで・説明 200字・いつの時点の説明か（年と月） | 11〜13語 |
| 出典 | 1〜8本。社の名前 40字・記事の題 200字・URL（決まった報道の社のサイトの物だけ）・日時・日時の補足（100字まで）・読んだ所（Yahoo!ニュースなど）。段階3で、著者の名前の欄（80字まで。著者を書く決まりのある出どころだけ）を足しました | 出典の無い話題は載せない（D23） |
| 報じた社の名前 | 30社まで | 元記事のある社を先に並べる |
| 照合 | 照らし合わせた件数・直した件数・照合したモデル | |
| 確かめられなかった点 | 15まで。各 300字まで | |
| 強調（下の「強調」） | 1か所 2〜40字・1つの欄に3か所まで・1本で60か所まで | 要約に1〜2か所（ほかの欄は要点がある時に）・欄の字数の2割まで（短い欄は12字まで） |

- 上限を超える物は足せません。目安から外れた物（例: 要約が 220字）は足せますが、作業の報告で知らせます。上限は、試運転のいちばん長い物の約2倍か、目安に余裕を足した値です。
- 記録の文は、太字や箇条書きの記号の無い、ふつうの文です。記事の中の文が混じっても、画面の部品として動かないようにするためです（4.6）。強調も、文に記号を入れずに、文とは別に覚えます。

### 具体例（作り物）

2026年11月15日（日）12:00版の3位の話題なら、次のように覚えます。

- 順位の理由: 「子どもがいる世帯の多くに関わり、来年4月から変わるため」
- 地域・ジャンル: 国内・政治。重大印: なし。
- 見出し: 「〇〇手当の拡充で A 党と B 党が合意、財源は12月に決める」
- 要約: 「A 党と B 党は、〇〇手当を子ども1人あたり月5,000円増やすことで合意した。来年4月から支給する。必要なお金をどこから出すかは、まだ決まっていない。」（実際は 120〜200字。ここでは短くしています）
- 結論: 未確定。補足「決まったのは増やす額と始める時期。財源は12月の協議で決める」。
- だから何？: 暮らし・お金「子どもが2人いる世帯なら、月1万円増えます」など。世界の力関係は当てはまらない → 記録には「当てはまらない」の印だけを覚え、画面には「この話題では特になし」と出します。
- 当事者の主張:
  1. A 党（賛成）。主張「子育ての負担を軽くする」、理由「…」。
  2. B 党（条件付き。補足「財源しだい」）。主張「財源を示すなら賛成」、理由「…」。
  3. C 党（不明）→ 記録には「確かめられなかった」の印だけを覚え（理由も書かず、分からなかった事は「確かめられなかった点」に）、画面には「今回集めた報道では、主張を確かめられなかった」と出します。
- AI の見解と対立見解: 軸「政府・与党側 ⇔ 野党・批判側」、論点「家計をすぐ助けるか、将来の負担を重く見るか」、見解と対立見解の文。
- 経緯: 「2026年10月 ― A 党が拡充を公約にした」「2026年11月10日 ― B 党と協議を始めた」（1行ずつ、日付と出来事に分けて）。
- 続報: なし（初めて出た話題）。
- 用語: 「〇〇手当」（説明「子どもを育てる家庭に、国や市町村が配るお金」）、「衆議院」（別名「衆院」）、「与党」（いつの時点か「2026年11月」）など。
- 出典: 「〇〇通信『〇〇手当、月5,000円増で合意』2026年11月15日 9:30」と「△△新聞（××ニュースで読んだ。日時なし）」。××ニュースは、Yahoo!ニュースのように配信の記事を読める所の、作り物の名前です（このまとめの例は、すべて作り物です）。
- 報じた社: 〇〇通信・△△新聞・□□放送。一覧のカードには「報道: 〇〇通信・△△新聞 ほか（3社）」と出します。
- 照合: 32件を照らし合わせ、2件を直した。確かめられなかった点「財源の案の金額は確かめられなかった」。

### 決まった文は、記録には印だけ

次の文は記録には書かず、アプリが決まった文を出します。

- 「この話題では特になし」
- 「今回集めた報道では、主張を確かめられなかった」
- 「対立する見解は特になし（事実の報道のため）」
- 共通の注記（5.7）と、当事者の見出しの文・AI の話題の注記
- 「訂正:」の頭の言葉
- 用語の説明の「2026年11月時点」

印にすれば言い回しが揺れず（試運転では4件）、Claude が書く量も減ります。「（一般的な傾向）」の添え書きは、文の一部なので、文のまま覚えます。

## 強調（新しく足しました）

ご希望（文が全部平たんで、流し読みしづらい）に合わせた形です。文はふつうの文のまま覚え、別に「どの欄の、どの語句を強調するか」を覚えます。アプリが欄の文からその語句を探し、強調の印（太字など。見た目は最後の「新しく確かめたいこと」の 1 で選んでいただきます）を付けます。強調だけを拾い読みしても、何が起きたか・何が決まったか・何が決まっていないかが分かるのが理想です。

例（作り物）:

- 要約の文: 「〇〇市が建設を進めてきた新しい橋が15日に開通し、市の中心部と東部の住宅地が1本の道で結ばれた。長さは320メートルで、歩道と自転車の道も付く。市は朝夕の渋滞が2割ほど減る見通しを示した。通行料はまだ決まっていない。市は来年3月までに決めるとしている。」（126字）
- 強調する語句（文とは別に覚えます）: 「15日に開通」「通行料はまだ決まっていない」（2か所・19字・要約の約15%）。
- 強調だけを拾い読みすると「15日に開通」「通行料はまだ決まっていない」で、何が起きて、何が決まっていないかが分かります。「渋滞が2割ほど減る見通し」も大事ですが、3か所にすると要約の2割を超えるので、ここでは付けていません（見通しに付ける時は、決まった事と取り違えないよう「見通し」の言葉ごと付けます）。

決まりの要点（仕様書 5.12。ご希望に合わせて開発で決めた案です）:

- 付ける欄: 要約・結論の補足・だから何？の4つ・当事者の主張の中身・AI の見解・対立見解・経緯の行・続報の「何が新しいか」。見出し・用語の説明・出典・確かめられなかった点・主張の理由には付けません。
- 量: 要約には必ず1〜2か所。ほかの欄は、要点がある時だけ1〜2か所（付けない欄があってかまいません。長い欄でも3か所まで）。1か所は2〜25字ほどで、1つの欄の合計は欄の字数の2割まで（短い欄は12字まで。経緯の1行のような短い欄でも、1か所は付けられるように）。経緯は大事な行だけに1か所。
- 付ける物: 決まった事・数字・期限や日付・誰が何をしたか・影響の中身。「画期的」のような評価だけの言葉には付けません。疑いの段階の事・決まっていない事は、「〜の疑い」「まだ決まっていない」などの言葉ごと強調します。
- 公平: AI の見解と対立見解、主張を確かめられた当事者どうしには、同じ数だけ付けます。
- 欄の文のとおりの語句を、1字も変えずに抜き出します。用語の印と重なってもかまいません。クリップの文には付けません。
- 守り: 欄の文に無い語句・重なる語句・数や長さの上限を超える物（1つの欄に4か所以上・1か所が1字か41字以上・1本で61か所以上）・AI の見解と対立見解で数が違う物は、つなぎ口が断ります。欄の2割（短い欄は12字）を超える・主張を確かめられた当事者どうしで数がそろわない・要約に強調が無い、は断らずに作業の報告で知らせます。アプリも、見つからない語句は付けずに出します。照合の係も強調を確かめます。
- 書く係が語句を書く分だけ、使用量が少し増えます。見本では、強調だけを別に付けて20本で約27万トークン（試運転の版の約1割）でした。本番では書く時に一緒に付けるので、増えるのはもっと少ない見込みです。見た目は、見本で選んでいただきます（最後の「新しく確かめたいこと」の 1）。

## 訂正（新しく足しました）

前の版の「確かめたいこと」の 2 で、B を選んでいただいた形です。

- 出た後の話題に誤りが分かった時は、Claude が元の話題に「訂正」の短い記録（300字まで。何がどう誤りで、正しくは何か）を足し、アプリがその話題に付けて「訂正: …」と出します（例・作り物「訂正: 新しい橋の歩道の幅は 2メートルではなく 3メートルでした」）。話題を直すことも、版を作り直すこともしません。
- 名札は元の話題の名札と、訂正の文の指紋から作ります（同じ訂正を2回送っても1件）。足せるのは、30日の内で、アプリに出た話題だけです。1つの話題に10件まで（案）。
- 定期実行の作業の中でも、あなたが Claude とのチャットで頼んでも足せます（段階3。チャットの時は、訂正のほかは足さない作業にします）。チャットでは、クリップした文（見出しと版の日付が入ります）を貼って「ここが違う」と頼んでください。Claude が記事で確かめられた時だけ訂正を足します（確かめられない事は書きません。D23）。
- 訂正の記録に、誰が頼んだかの欄は持たず、Claude には訂正の文だけを渡します（D21）。ただし、作った時刻などから、チャットで頼んだ物だと分かることはあります（下の「Claude（つなぎ口）との関係」）。
- 訂正も直さず・消さず、訂正の誤りはもう1つ訂正を足して正します。元の話題と一緒に30日で消えます。大きな続きは次の版の続報でも書き、用語の辞書の誤りは新しい説明を足して直します。
- 読み終えた話題の訂正は、前の版を開き直さない限り目に入りません。見た目や、次の版の上で静かに知らせるかは、段階2の画面で確かめます（通知・音・数字は出しません。D9）。

## 続報のつなぎ方

どの話題にも「続報をつなぐ番号」を持たせます。初めて出た話題は、自分の名札をそのまま使います。続報は、前の話題の番号を写します。この番号は Claude に作らせず、Claude が「この話題の続き」と前の話題を指すと、つなぎ口が写します（作り間違えないように）。

例（作り物）:

1. 11/15 12:00版「〇〇市で新しい橋が開通」 → 初めて出た話題。
2. 11/16 20:00版「〇〇市の新しい橋、開通後の渋滞が2割減」 → 続報。「何が新しいか: 市が開通後1日の交通量を発表した」。経緯の行に「11月15日 ― 新しい橋が開通」が入ります。

2つは同じ番号なので、追いつき（見ていない版をまとめて出す案。9.）では最新の 2. だけを出せます。1. が30日で消えても、つながりは切れません。続報には経緯（これまでの流れ）を必ず付けます。

## 用語の辞書と「知ってる」

### 用語の辞書

辞書の1つの語には、表記・別名（「衆議院」と「衆院」のように、表記の違う同じ語。10まで）・説明・いつの時点の説明か・何回目の説明かを覚えます。

- その版で新しく使う語は、話題より先に辞書に足します。話題の用語の説明と別名は、つなぎ口が辞書から写します（Claude は語を指すだけ）。（段階3で替えました: 足す順は同じで、辞書に足すのはつなぎ口です。Claude は下書きの中で新しい語と説明を書き、つなぎ口が、照合の済んだ下書きの新しい語を1つのまとまりにして、話題より先に足します）試運転では、同じ版の中でも話題ごとに説明がぶれましたが、この順ならぶれず、使用量も減ります（15.3）。
- 1つの話題の中では、1つの表記は1つの語にだけ属します。国によって中身の違う語（与党など）は、「与党（日本）」「与党（米国）」のように別の語として持ちます。
- 誤りや、時期で中身が変わった語は、説明を直す代わりに新しい説明を足します（Claude は直せず、辞書は消さないので）。使わなくなった語には「外した」の印を足します。
- **前に出た話題の説明は、その話題が出た時のまま**にします（作者の答えの 3。D26）。新しい話題からは新しい説明を出します。時期で変わる語には、新しい話題でも古い話題でも「2026年11月時点」のように、いつの説明かを添えます。アプリは辞書を受け取らず（説明が新しくなったかを知らないので、時点はいつも添えます）、話題に写した説明と別名を出します。
- 辞書は版ごとに「その版で足した語」を1つのまとまりにして足します（1語ずつだと記録の数が多くなりすぎるため）。辞書は消しません。説明はふつうの文だけにし、Claude は資料として読みます（指示としては読みません）。

### 「知ってる」

- 1つの語に1つの記録です。名札は語から作るので、2台で押しても、別名（「衆院」）で押しても、同じ1件になります。
- 外す時は記録を消さず、「知らない」に切り替えます（2台で付けた・外したが食い違わないように）。設定の「知ってる」にした語の一覧から、いつでも戻せます。
- 押した時の説明の「いつの時点か」も覚えます（何度か押した時は、いちばん新しい時点）。時期で変わる語の説明が新しくなったら、新しい説明の話題でだけ、その語をもう一度出します（5.8）。古い話題で押しても、新しい説明の「知ってる」は外れません。
- Claude には、いまの説明で「知ってる」語の一覧だけを渡します。押した日時・時点は渡しません。（段階3で替えました: 一覧は渡さず、Claude が辞書を引いた時に、その語を「いまの説明で知ってる」かだけを返します）

## 作れなかった時

版を作れなかった時は、Claude が「作れなかった印」（どの版か・理由の種類・短い理由 200字まで）を足し、アプリは前の版を出したまま「12:00版は作れませんでした（使用量の上限）」と静かに出します（4.7）。後から同じ版を作れた時は版を出します。作業そのものが動かなかった時は、時刻だけを見て「まだ届いていません」のように出します（言葉は段階2）。

## 既読と、見た版

- 版1つに1つの記録で、読んだ話題の名札と、その版の一覧を見たか（追いつきに使います）を覚えます。PC で1本目、スマホで2本目を読んだら、両方とも既読になります。
- 既読は画面の出し方（「既読 n件」にまとめて沈めるなど）にだけ使い、選ぶ話題・並び・本数には使いません（D21）。版と一緒に30日で消えます。
- どの操作で既読にするか・既読を戻す操作を作るかは、段階2の画面で決めます（覚え方はどちらでも同じです）。

## クリップ（記録は持ちません）

前の版の「確かめたいこと」の 1 へのお答え（保存はあまり要らない。元記事の URL ごとコピーして、ほかのメモ帳に貼れればよい）に合わせた形です。保存の機能は作りません。

- 話題の詳細に［クリップ］を置きます（一覧のカードにも置くかは段階2）。押すと、見出し・版（日付と 12:00版・20:00版）・地域とジャンル・要約・元記事（社の名前・記事の題・URL）を、ふつうの文として端末にコピーします。ほかのメモ帳に、そのまま貼れます。形の案（作り物。言葉や並びは段階2で決めます）:

## 端末ごとの設定（同期しない）

外観、起動アニメーションのオン・オフ、文字の大きさ（段階2で決めます）、この端末で持ち主だと確かめたアカウント、最後に見ていたジャンルの位置などです。その端末だけで覚えます。

## 消す時（30日）

- 版と話題は、版の日付の30日後の 0時（日本時間）に消えます。たとえば 11/15 の版は、12/15 の 0時に消えます（11/15〜12/14 の30日間、読めます）。訂正・既読・作れなかった印も、版と一緒に消えます。消えない物は、「知ってる」と用語の辞書だけです。
- 消すのはアプリです（Claude は消せません）。開いている窓のうち1つが、1日に1回、操作の無い時に消します。
- クラウドから消す時は、端末の時計ではなくクラウドの時刻の見積もりで決め、クラウドの決まりでも30日を過ぎていない版は消せないようにします（早く消さないように）。
- 消したことをほかの端末に知らせる印は書きません。どの端末も、同じ日付の決まりで自分の中から消します。
- 長い間どの端末も開かなかった時は、最初に開いた端末がまとめて消します（1台が1日に 2,000件まで）。

## 端末とクラウド

- **画面は端末の中だけを見ます**。電波が無くても、届いている版は読めます。**新しい版**は、アプリを開いている間か、次に開いた時に届きます。
- **既読・「知ってる」**は、変えてから2秒後（続けて変えても10秒まで）か、画面を閉じる・裏に回る時に送ります。電波が無い間は端末にとっておき、つながったら送ります。
- **2台で食い違った時**: 既読は両方の分を足し合わせます。「知ってる」は、電波の無い間に2台で付けた・外したが食い違ったら、後から同期した端末の方を採ります。Claude が足した物は誰も書き換えないので、食い違いは起きません。
- **新しい端末**では、最初に「知ってる」を全部と、30日分の版・話題（約60版・約1,200本）・訂正・作れなかった印・既読を受け取ります。30日より前の物と、用語の辞書（Claude が使う物）は受け取りません。
- **同期の表示**（ヘッダーの右）は Diary Studio と同じ8つです。長く「受け取り中」のままなら、お知らせください。持ち主の記録が消えていた時・前に別のアカウントで使っていた端末・更新していない古いアプリ（「要更新」）は、Diary Studio と同じように同期を止めて知らせます。

### 無料枠の見積もり

1日に版2つ（40本）・端末3台・1日に10回ほど開く・「知ってる」を1日10語・訂正は1日0〜数件、で見積もりました（保存を作らないので、その分は入りません）。「読み取り」などは、クラウドの記録を1件読む・書くたびに1回と数えます。

| 書き込み 1日2万回 | 約 140回（Claude が足す約 44〜50回を含む） |

## 段階1を過ぎると変えにくい物

- 名札の決め方（版は日付と時刻、話題は版と中身の指紋、訂正は元の話題と中身の指紋、語は表記、既読は版）。後から変えると、続報のつながりや「知ってる」が切れます。
- 置き場の分け方（Claude が読める・読めない）。
- 各記録に何を覚えるかと、その意味。特に選べる値（地域2つ・ジャンル7つ・結論3つ・立場4つ）の意味や分け方（例: 「事故・事件」を2つに分けること）。
- 強調を、文とは別に「どの欄の、どの語句か」で覚えること。出た後の誤りを、話題を直さずに訂正を足して直すこと。決まった文をアプリが出すこと。

## 後から足せる物

- 選べる値を足すこと（例: ジャンルに「科学」を足す）や、新しい欄・話題とは別の新しい記録（例: 小説のネタ。12.）。古い版のアプリは、知らない値・欄を消さずに残します。

## 開発で決めたこと

1. 既読・見た版は、Claude が読めない置き場に置きます（保存を作らないので既読だけですが、分ける作りは残します）。
2. 版・話題・訂正・作れなかった印・既読は30日で消し、消すかどうかは日付だけで決めます。30日は版の日付から数え、30日後の 0時（日本時間）に消えます。
3. 版の日付と、12:00版・20:00版は日本時間で決めます。
4. 決まった文は、アプリが出します（記録には印だけ）。
5. 社の名前の書き方は決まった一覧にそろえ、元記事のある社を並びの先に置きます。「n社」は、覚えた社の名前の数にします（試運転では数が合わない物が多くありました）。
6. 出典の日時は「日時」と「補足の文」（「掲載日時は不明」など）に分けます。
7. 経緯は、1行ずつ「日付」と「出来事」に分けて覚えます。日付は記事に書かれたまま（日本時間に直しません）で、日付の無い行も書けます。
8. 選ばなかった見出しと候補の数を、版と一緒に30日残します（のぞく画面は後で）。
9. 用語の辞書は Claude が使う物で、端末には入れません。アプリは話題に写した説明と別名を出します。
10. PC で見た版は、スマホでも「見た」ことにします（見た版も端末どうしでそろえます）。
11. 訂正は、30日の内でアプリに出た話題にだけ足せます。1つの話題に10件まで（案）。チャットから頼む訂正は「訂正だけ」の作業にします（段階3で決めます）。
12. 強調は、上の「決まりの要点」の欄だけに付けます。合わない語句はアプリが付けずに出し、記録は直しません。
13. 新しい端末は、30日より前の既読も受け取りません。
14. 強調の量の目安は、1つの欄の合計が欄の字数の2割まで（短い欄は12字まで）とし、超えても断らずに作業の報告で知らせます。
15. Claude に渡す訂正は文だけにします（いつ・どの作業で足したかは渡しません）。チャットで頼む訂正のために、Claude が30日の内の話題を、版の日付と見出しで探せるようにします（段階3）。
