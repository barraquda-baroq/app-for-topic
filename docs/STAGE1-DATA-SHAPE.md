# 段階1で固める「データの形」のまとめ（作者の方へ）

2026-11-15 時点

## はじめに：今どこまで出来ているか

段階0（土台）は出来上がっていて、https://topic-studio-1a463.web.app に公開済みです。起動アニメーション、ログインの画面、持ち主の確かめ、空のトップ画面、外観の切り替えまでが動きます。

段階0.5（試運転）も済みました。アプリを使わずに、本番と同じ流れで1回の版（20本）を作り、どんな中身になるかを確かめました。このまとめの「何を覚えるか」は、その時の形を元にしています。

段階1（データと同期）は、まだ作り始めていません。本物の版がアプリに届くのは段階3（Claude とのつなぎ口を作る段階）からなので、段階1では作り物の版を入れて確かめます。

このまとめは、仕様書（7.）の「データの持ち方（案）」を、作る前に分かりやすく書き直した物です。段階1を作り終えた時に、出来た物とこのまとめが合っているかを、改めてお知らせします。最後の「確かめたいこと」に答えていただけると助かります。

## このまとめで使う言葉

- **記録**: アプリが覚える1件のまとまり（1つの版、1本の話題など）。
- **名札**: 記録を見分けるための番号。
- **端末**: PC・スマホなど、アプリを開く機械。
- **クラウド**: Firebase（Google のデータの置き場）。あなたのアカウントだけが読める所に置きます。
- **同期**: 端末とクラウドの中身をそろえること。
- **つなぎ口（コネクタ）**: Claude がアプリに版を足すための入口。段階3で作ります。
- **置き場**: クラウドの中の棚。「Claude が読める置き場」と「Claude が読めない置き場」の2つに分けます。
- **指紋**: 記録の中身から計算した短い印。中身が同じなら同じ印になります。

## なぜ「固める」のか

段階1が終わると、PC・スマホのそれぞれの端末とクラウドに記録が溜まり始めます。版と話題は30日で入れ替わるので、Diary Studio より後から変えやすい方ですが、次の物はずっと残ります。

- 保存した話題（無期限）
- 「知ってる」にした用語
- 用語の辞書

また、段階3で作るつなぎ口とアプリは、同じ形の記録をやり取りします。名札の付け方や置き場を後から変えると、続報のつながりや「知ってる」が切れたり、Claude に見せない物の守りを作り直したりすることになります。そのため、段階1の前に固めます。

## 全体の絵：誰が何を書くか

| 記録 | 書くのは | 置き場 | いつ消えるか |
|---|---|---|---|
| 版（1回の更新） | Claude | Claude が読める | 30日 |
| 話題（1本ずつ） | Claude | Claude が読める | 30日 |
| 用語の辞書 | Claude | Claude が読める | 消さない |
| 作れなかった印 | Claude | Claude が読める | 30日 |
| 「知ってる」にした用語 | あなた（アプリ） | Claude が読める | 消さない |
| 既読（と、見た版） | あなた（アプリ） | Claude が読めない | 30日 |
| 保存した話題 | あなた（アプリ） | Claude が読めない | 消さない |

- Claude ができるのは「足す」ことだけです。足した物を直すことも、消すこともできません。
- アプリは、Claude が足した記録を書き換えません。30日が来たら消すだけです。
- 既読と保存は「あなたが何を読んだか」の記録なので、Claude が読めない置き場に置きます（個人に合わせない決まり。D21）。Claude に渡すあなたの情報は「知ってる」にした用語だけです。

## すべての記録に共通して覚えること

- 名札。
- 作った日時。世界共通の時計で覚え、画面に出す時だけ日本時間に直します。
- 誰が作ったか（Claude か、あなたか）と、どの AI か（今は Claude だけ）。
- 記録の形の版。今はすべて 1 です。
- Claude が作った物には、さらに「作ったモデルの名前」（60字まで。Claude が自分で名乗った物）と「どの定期実行の回か」（つなぎ口が付けます）。Fable 以外のモデルで動いたかの目安になります（D7）。
- あなたが書く物（既読・保存・「知ってる」）には、さらに「最後に変えた日時」。

## 版（1回の更新）

1つの版に1つの記録です。名札は日付と時刻だけで決まります（例: 2026年11月15日の 12:00版）。日付は日本時間で決めるので、端末の時計を海外に合わせても、12:00版は日本時間の 12:00 の版です。どの時刻の版かは、Claude ではなくつなぎ口が、作業を始めた時刻で決めます（取り違えて、別の時刻の版の名札を埋めないように）。

覚えるのは次のことです。

- 日付と、12:00版か20:00版か。
- 話題の並び（知るべき順）。ふだんは20本で、30本までにします。
- 候補の数（例: 集めた記事 388件）と、選ばなかった主な見出し（20件まで）。AI の選び方を、あなたが後からのぞけるようにするためです（6.5）。どこに出すかは段階2で決めます。
- 候補を集めた時間の窓（例: 11/14 18:30 から 11/15 10:30 まで）。
- 使用量（測れる時だけ）。

Claude は、話題を全部足し終えてから、最後に版の記録を足します。アプリは、版の記録が届いた時に初めてその版を出します。途中で止まった版（話題だけ届いて、版の記録が無い）は出ません。

## 話題（1本）

1本の話題に1つの記録です。名札は「どの版か」と「中身の指紋」から作ります（例: 2026-11-15-12 と、8字の印）。同じ物を2回送っても1件のままで、Claude が書き直した物は別の名札になるので、やり直しても前の物とぶつかりません。どちらを出すかは、版の記録の並びで決まります。

### 覚えること

| 覚えること | 長さ・数の上限 | 決まりの目安 |
|---|---|---|
| どの版か・順位と短い理由 | 理由 200字まで | |
| 地域 | 国内か世界のどちらか | |
| ジャンル | 政治、経済、テクノロジー、AI、事故・事件、スポーツ、エンタメの、どれか1つ | |
| 重大印 | ある・なし | 1日に0〜3件 |
| 見出し | 60字まで | 30字台 |
| 要約 | 300字まで | 120〜200字（空白を除く） |
| 結論 | 確定・未確定・見通しのどれかと、補足（200字まで）と、速報・未確認の印 | |
| だから何？ | 4つの観点（暮らし・お金、社会の仕組み、世界の力関係、なぜ話題か）。各 800字まで | |
| 当事者の主張 | 15まで。名前 60字・立場（賛成・反対・条件付き・不明）と、その補足 60字・主張 400字・理由 300字 | 政治は議席の多い順 |
| AI の見解と対立見解 | 軸の名前 80字・論点 150字・見解と対立見解は各 800字まで。「対立見解なし」の時は、その印と（あれば）理由 200字 | 分量の差は1割まで |
| 経緯 | 12行まで。1行に「日付」（記事に書かれたまま。無い行もある）と「出来事」（160字まで） | 書いた順に並べる |
| 続報 | 前の話題と、何が新しくなったか（200字まで） | |
| 用語 | 20語まで。表記 40字・別名 10まで・説明 200字・いつの時点の説明か（年と月） | 11〜13語 |
| 出典 | 1〜8本。社の名前 40字・記事の題 200字・URL（決まった報道の社のサイトの物だけ）・日時・日時の補足（100字まで）・読んだ所（Yahoo!ニュースなど） | 出典の無い話題は載せない（D23） |
| 報じた社の名前 | 30社まで | 元記事のある社を先に並べる |
| 照合 | 照らし合わせた件数・直した件数・照合したモデル | |
| 確かめられなかった点 | 15まで。各 300字まで | |

- 上限を超える物は足せません。目安から外れた物（例: 要約が 220字）は足せますが、Claude の作業の報告で知らせます。
- 試運転の版は、1本が約 1,900〜4,150字でした（出典・確かめられなかった点まで数えたので、仕様書 15.6 の約 1,900〜3,800字より多めです）。上の上限は、試運転のいちばん長い物の約2倍か、決まりの目安に余裕を足した値です。
- 記録の文は、太字や箇条書きの記号の無い、ふつうの文です。記事の中の文が混じっても、画面の部品として動かないようにするためです（4.6）。

### 具体例（作り物）

2026年11月15日（日）12:00版の3位の話題なら、次のように覚えます。

- 順位の理由: 「子どもがいる世帯の多くに関わり、来年4月から変わるため」
- 地域・ジャンル: 国内・政治。重大印: なし。
- 見出し: 「〇〇手当の拡充で A 党と B 党が合意、財源は12月に決める」
- 要約: 「A 党と B 党は、〇〇手当を子ども1人あたり月5,000円増やすことで合意した。来年4月から支給する。必要なお金をどこから出すかは、まだ決まっていない。」（実際は 120〜200字。ここでは短くしています）
- 結論: 未確定。補足「決まったのは増やす額と始める時期。財源は12月の協議で決める」。
- だから何？: 暮らし・お金「子どもが2人いる世帯なら、月1万円増えます」、社会の仕組み「手当は国と市町村がお金を分けて出す仕組みです…」など。世界の力関係は当てはまらない → 記録には「当てはまらない」の印だけを覚え、画面には「この話題では特になし」と出します。
- 当事者の主張:
  1. A 党（賛成）。主張「子育ての負担を軽くする」、理由「…」。
  2. B 党（条件付き。補足「財源しだい」）。主張「財源を示すなら賛成」、理由「…」。
  3. C 党（不明）→ 記録には「確かめられなかった」の印だけを覚え（理由も書きません。何が分からなかったかは「確かめられなかった点」に書きます）、画面には「今回集めた報道では、主張を確かめられなかった」と出します。
- AI の見解と対立見解: 軸「政府・与党側 ⇔ 野党・批判側」、論点「家計をすぐ助けるか、将来の負担を重く見るか」、見解と対立見解の文。
- 経緯: 「2026年10月 ― A 党が拡充を公約にした」「2026年11月10日 ― B 党と協議を始めた」（1行ずつ、日付と出来事に分けて）。
- 続報: なし（初めて出た話題）。
- 用語: 「〇〇手当」（説明「子どもを育てる家庭に、国や市町村が配るお金」）、「衆議院」（別名「衆院」）、「与党」（説明「いま政府を作っている政党。A 党と B 党」、いつの時点か「2026年11月」）など。
- 出典: 「〇〇通信『〇〇手当、月5,000円増で合意』2026年11月15日 9:30」と、「△△新聞（Yahoo!ニュースで読んだ。日時は記事に無かった）」。
- 報じた社: 〇〇通信・△△新聞・□□放送。一覧のカードには「報道: 〇〇通信・△△新聞 ほか（3社）」と出します。
- 照合: 32件を照らし合わせ、2件を直した。確かめられなかった点「財源の案の金額は確かめられなかった」。

### 決まった文は、記録には印だけ

「この話題では特になし」「今回集めた報道では、主張を確かめられなかった」「対立する見解は特になし（事実の報道のため）」・共通の注記（5.7）・当事者の見出しの文・AI の話題の注記は、記録には書かず、アプリが決まった文を出します。試運転では、言い回しが揺れた物が4件、共通の注記を話題の文の中に書いた物が1件ありました。印にすれば揺れず、Claude が書く量も少し減ります。

「（一般的な傾向）」の添え書きは、文の一部なので、文のまま覚えます。

## 続報のつなぎ方

どの話題にも「続報をつなぐ番号」を持たせます。初めて出た話題は、自分の名札をそのまま使います。続報は、前の話題の番号を写します。この番号は Claude に作らせず、Claude が「この話題の続き」と前の話題を指すと、つなぎ口が写します（作り間違えないように）。

例（作り物）:

1. 11/15 12:00版「〇〇市で新しい橋が開通」 → 初めて出た話題。
2. 11/16 20:00版「〇〇市の新しい橋、開通後の渋滞が2割減」 → 続報。「何が新しいか: 市が開通後1日の交通量を発表した」。経緯の行に「11月15日 ― 新しい橋が開通」が入ります。

2つは同じ番号なので、追いつき（しばらく開かなかった後に、見ていない版をまとめて出す案。9.）では最新の 2. だけを出し、一覧には続報の印を出せます。1. が30日で消えた後も、番号は 2. に残るので、つながりは切れません。続報には経緯（これまでの流れ）を必ず付けます（途中から読んでも追いつけるように）。

## 用語の辞書と「知ってる」

### 用語の辞書

辞書の1つの語には、表記・別名（「衆議院」と「衆院」のように、表記の違う同じ語。10まで）・説明・いつの時点の説明か・何回目の説明かを覚えます。

- Claude は、その版で新しく使う語を、話題より先に辞書に足します。話題の用語の説明と別名は、つなぎ口が辞書から写します（Claude は語を指すだけ）。試運転では、同じ版の中で2本以上の話題に出た 11語のうち 8語が、話題ごとに違う説明になっていました。この順なら、同じ版の中でもぶれません。説明を2回書かずに済むので、使用量も減ります（15.3）。
- 1つの話題の中では、1つの表記は1つの語にだけ属します（試運転では、1つの表記が2つの語に属した物が 10ありました）。国によって中身の違う語（与党など）は、「与党（日本）」「与党（米国）」のように、国ごとに別の語として持ちます。
- 誤りや、「いまの与党は〜」のように時期で中身が変わった語は、説明を直す代わりに、新しい説明を足します（Claude は直せず、辞書は消さないので）。いちばん新しい説明を使います。使わなくなった語には「外した」の印を足します。
- 辞書は版ごとに「その版で足した語」を1つのまとまりにして足します（1語ずつだと、何年も使ううちにクラウドの記録の数がとても多くなるため）。
- 辞書は Claude が使う物で、アプリは話題に写した説明と別名を出します。辞書が後で新しくなっても、その日の話題の説明は変わりません（確かめたいことの 3）。
- 辞書は消しません。説明はふつうの文だけにし、Claude は資料として読みます（指示としては読みません）。

### 「知ってる」

- 1つの語に1つの記録です。名札は語から作るので、2台で押しても1件になります。別名（「衆院」）で押しても、同じ語の記録になります。
- 外す時は記録を消さず、「知らない」に切り替えます。2台で付けた・外したが食い違わないようにするためです。消さないので、設定の「知ってる」にした語の一覧から、いつでも戻せます。
- 押した時の説明の「いつの時点か」も覚えます（何度か押した時は、いちばん新しい時点）。時期で変わる語の説明が新しくなったら、新しい説明の話題でだけ、その語をもう一度出します（5.8）。古い話題で押しても、新しい説明の「知ってる」は外れません。
- Claude には、いまの説明で「知ってる」語の一覧だけを渡します。押した日時・時点は渡しません。

## 作れなかった時

版を作れなかった時は、Claude が「作れなかった印」を足します。覚えるのは、どの版か・理由の種類（使用量の上限・障害・時間切れ・読める記事が足りない・そのほか）・短い理由（200字まで）です。アプリは前の版を出したまま、「12:00版は作れませんでした（使用量の上限）」と静かに出します（4.7）。

この印は版とは別の名札にするので、後から同じ版を作れた時は、印があっても版を出します。Claude の作業そのものが動かなかった時は印も無いので、アプリは時刻だけを見て「まだ届いていません」のように出します（言葉は段階2）。

## 既読と、見た版

- 版1つに1つの記録で、その版で読んだ話題の名札を並べて覚えます。その版の一覧を見たかどうか（追いつきに使います）も覚えます。
- PC で1本目、スマホで2本目を読んだら、両方とも既読になります（2台で別々に読んでも両方残ります）。
- 既読は「既読 n件」にまとめて下へ沈める、追いつきに見ていない版だけを出す、といった画面の出し方にだけ使います。選ぶ話題・並び・本数には使いません（D21）。
- 版と一緒に30日で消えます。
- どの操作で既読にするか（詳細を開いた時か、など）と、既読を戻す操作を作るかは、段階2の画面で決めます。覚え方はどちらでも同じです。

## 保存

- 保存の印を付けた時に、その話題の中身をまるごと写して覚えます（1本 約3,000字）。元の版が30日で消えても、保存した話題は残ります（無期限。D10）。
- 保存した後に続報（不起訴など）が出たら、保存した話題に「続報: 何が新しいか」を小さく付け足して残します（続報の本文は写しません。5.9）。確かめたいことの 2 で B を選んだ時は、訂正も同じく付け足します。
- 保存を外した時は、写しを30日とっておき、その間は戻せます（戻す画面は段階2）。30日たったら写しを消し、印を「外した」にした小さな記録だけが残ります。2台で付けた・外したが食い違わないようにするためです。
- Claude が読める置き場の話題は、保存したかどうかに関わらず、同じ日に消えます（保存した話題だけを残すと、残っている話題から保存したと Claude に分かるため）。保存した写しは、Claude が読めない置き場にあります。
- 続報も残すかは、確かめたいことの 1 です。

## 端末ごとの設定（同期しない）

外観、起動アニメーションのオン・オフ、文字の大きさ（段階2で決めます）、この端末で持ち主だと確かめたアカウント、最後に見ていたジャンルの位置などです。その端末だけで覚えます。

## 消す時（30日）

- 版と話題は、版の日付の30日後の 0時（日本時間）に消えます。たとえば 11/15 の版は、12/15 の 0時に消えます（11/15〜12/14 の30日間、読めます）。既読と作れなかった印も、版と一緒に消えます。
- 消えない物は、保存した話題・「知ってる」・用語の辞書です。
- 消すのはアプリです（Claude は消せません）。アプリを開いている窓（タブ）のうち1つが、1日に1回、操作の無い時に消します。外して30日たった保存の写しも、この時に消します。
- クラウドから消す時は、端末の時計ではなく、クラウドの時刻の見積もりで決めます。クラウドの決まりでも、30日を過ぎていない版は消せないようにします。時計が進んだ端末や計算の誤りで、早く消してしまわないようにするためです。
- 消したことをほかの端末に知らせる印は書きません。どの端末も、同じ日付の決まりで自分の中から消します。
- 長い間どの端末も開かなかった時は、最初に開いた端末がまとめて消します。無料枠を使い切らないよう、1台が1日に 2,000件までにします。

## 端末とクラウド

- **画面は端末の中だけを見ます**。電波が無くても、届いている版は読めます。ログインと同期以外は動きます。
- **新しい版**は、アプリを開いている間に届きます。開いていない時は、次に開いた時に届きます。
- **既読・保存・「知ってる」**は、変えてから2秒後（続けて変えても10秒まで）か、画面を閉じる・裏に回る時に送ります。電波が無い間は端末にとっておき、つながったら送ります。
- **2台で食い違った時**:
  - 既読は、両方の分を足し合わせます。
  - 保存・「知ってる」は、電波の無い間に2台で付けた・外したが食い違ったら、後から同期した端末の方を採ります。
  - Claude が足した物は誰も書き換えないので、食い違いは起きません。
- **新しい端末**では、最初に、30日分の版と話題（約60版・約1,200本）と、「知ってる」と、保存した話題と、既読を受け取ります。30日より前の版と話題は受け取りません。用語の辞書も受け取りません（Claude が使う物なので）。
- **同期の表示**（ヘッダーの右）: 同期済み・送信中・未送信 n件・受け取り中・オフライン・今日の無料枠を使い切りました（{時刻} ごろに戻ります）・要更新・同期できません（理由）の8つです（Diary Studio と同じ）。ふだんは「同期済み」で、新しい版が届く間だけ「受け取り中」になります。長く「受け取り中」のままなら、お知らせください。
- **持ち主の記録が消えていた時**（「同期できません（持ち主の記録がまだありません）」。14.8 の 4）、**前に別のアカウントで使っていた端末**（14.4）、**覚え方を変えた新しい版のアプリが出た後の、更新していない古いアプリ**（「要更新」）は、Diary Studio と同じように同期を止めて知らせます。

### 無料枠の見積もり

1日に版2つ（40本）・端末3台・1日に10回ほど開く・「知ってる」を1日10語・保存を1日2本、で見積もりました。「読み取り」などは、クラウドの記録を1件読む・書くたびに1回と数えます。

| 無料枠 | 見積もり |
|---|---|
| 読み取り 1日5万回 | ふだんの日で約 500回（約1%）。新しい端末の初めての受け取りは、1年目で約 2,000〜6,000回 |
| 書き込み 1日2万回 | 約 150回（Claude が足す約 45回を含む） |
| 削除 1日2万回 | 約 45回（30日を過ぎた版2つと話題40本） |
| 保存の量（合計） | 1年目で無料の量の約3〜6%。10年使っても約45%まで（いちばん伸びるのは用語の辞書） |
| 1件に入る量 | いちばん大きい話題でも、1件に入る量の約16%。分けて置く必要はありません |

段階3の Claude のつなぎ口は、アプリの分を残すため、読み取りを自分で1日 15,000回までに止めます（Novel Studio と同じ）。

## Claude（つなぎ口）との関係

つなぎ口は段階3で作ります。段階1では、置き場の分け方と名札の決め方を固めておきます。

| | 版・話題・作れなかった印 | 用語の辞書 | 「知ってる」 | 既読・見た版・保存 |
|---|---|---|---|---|
| Claude が読む | 読む（続報をつなぐため、直近数日の話題を短い形で） | 読む（使いそうな語だけ） | 読む（いまの説明で知ってる語だけ） | **読めない** |
| Claude が足す | 足すだけ | 足すだけ | できない | できない |
| Claude が直す・消す | できない | できない | できない | できない |

- 「読めない」は、つなぎ口の作りだけでなく、クラウドの決まり（誰が何を読める・書けるかの決まり）でも止めます。置き場ごと分けるので、つなぎ口の作りに誤りがあっても読めません。
- つなぎ口の入り方は Novel Studio と同じにする見込みです（あなたが最初に1回許可し、つなぎ口はあなたの Google のアカウントを使わず、専用の合鍵でクラウドに入ります。アプリの連携の画面で許可している間だけ書けます）。
- 定期実行は人のいない作業なので、読む道具と足す道具は「常に許可」にします。TS には直す・消す道具がありません。
- 記事の中に AI への指示のような文があっても、Claude は従いません。アプリも、記録の文をふつうの文として出します（リンクにするのは、決まった報道の社のサイトの出典だけ）。
- 候補の記事や記事の本文は、クラウド（Firebase）には入れません（Cloudflare 側で候補を集め、版を作る作業のためだけに使い、作り終えたら消します。4.2）。
- つなぎ口は、毎回全部を読まずに済むよう、Claude が読める置き場の写し（版・話題・辞書・「知ってる」）を Cloudflare 側に持ちます。既読・保存の写しは持ちません。
- クラウドの決まりの上では、つなぎ口から「知ってる」を押したおおよその時刻・端末の数と、アプリを開いた日（30日の片付けをした日）は見えます。つなぎ口はこれを Claude に渡しません。

## 段階1で確かめる方法

作り物の版（「〇〇市で新しい橋が開通」「A 党と B 党」「〇〇通信」のような中身）を、テスト用のクラウド（エミュレーター。手元で動く練習用の Firebase）に入れて、2台の端末の同期・30日で消す・保存した話題が残る、などを確かめます。段階1のトップ画面には、届いた版の見出しだけを並べる仮の一覧を出します（見た目は段階2）。リポジトリは公開なので、本物のニュースはテストにも見本にも使いません。

## 段階1を過ぎると変えにくい物

- 名札の決め方（版は日付と時刻、話題は版と中身の指紋、語は表記、既読は版、保存は話題）。後から変えると、続報のつながりや「知ってる」が切れます。
- 置き場の分け方（Claude が読める・読めない）。
- 各記録に何を覚えるかと、その意味。特に選べる値（地域2つ・ジャンル7つ・結論3つ・立場4つ）の意味や分け方（例: 「事故・事件」を2つに分けること）。
- 保存した話題を写して持つこと。
- 決まった文をアプリが出すこと。

## 後から足せる物

- 選べる値を足すこと（例: ジャンルに「科学」を足す）。古い版のアプリは、知らない値を消さずに残します。
- 新しい欄や、話題とは別の新しい記録（例: 小説のネタ。12.）。古い版のアプリは、知らない欄を消しません。
- 画面（段階2）と、Claude とのつなぎ口（段階3）。
- バックアップ（書き出し）。確かめたいことの 4 です。
- アプリで辞書を見る画面（用語集など）。

## 開発で決めたこと

1. 既読・保存・見た版は、Claude が読めない置き場に置きます。
2. 保存した話題は写して残し、Claude が読める置き場の話題は、保存に関わらず30日で消します。
3. 30日は版の日付から数え、30日後の 0時（日本時間）に消えます。
4. 版の日付と、12:00版・20:00版は日本時間で決めます。
5. 決まった文は、アプリが出します（記録には印だけ）。
6. 社の名前の書き方は決まった一覧にそろえ（一覧に無い社は、そのままの名前で入れます）、元記事のある社を並びの先に置いて、一覧のカードにはその社の名前を出します。「n社」は、覚えた社の名前の数にします（試運転では、出典の社が並びとそろわない物・数が合わない物が多くありました）。
7. 出典の日時は「日時」と「補足の文」（「掲載日時は不明」など）に分けます（試運転では日時の書き方が5通りありました）。
8. 経緯は、1行ずつ「日付」と「出来事」に分けて覚えます。日付は記事に書かれたまま（日本時間に直しません）で、日付の無い行も書けます。
9. 選ばなかった見出しと候補の数を、版と一緒に30日残します（のぞく画面は後で）。
10. 用語の辞書は Claude が使う物で、端末には入れません。アプリは話題に写した説明と別名を出します。
11. PC で見た版は、スマホでも「見た」ことにします（見た版も端末どうしでそろえます）。

## 確かめたいこと

1〜3 は、段階1を公開する前に答えが要ります（覚え方が変わるため）。4 は急ぎません（どちらでも覚え方は同じです）。

### 1. 保存した話題は、どこまで残すか

- **A（おすすめ）**: 保存の印を付けた時の、その1本だけを写して残します。その後に続報が出ても、保存した中身は変わりません（「続報: 何が新しいか」だけを付け足します）。続報も残したい時は、続報にも保存の印を付けます。続報には経緯（これまでの流れ）が付くので、最新の続報を保存すれば流れも分かります。
- **B**: 保存の印を「その出来事」に付け、後から出る続報も、アプリが自動で写して残します。保存した出来事の続報は、30日を過ぎても消えなくなります（作りが少し複雑になります）。30日より長くアプリを開かなかった間の続報は残せません。
- どちらでも、外した保存は30日たってから写しを消します。

### 2. 出た後の話題に誤りが見つかった時の直し方

背景: Claude がアプリにできるのは「足す」ことだけで、出た話題を後から直せません。照合（4.5）を済ませてから足しますが、それでも後で誤りが分かることがあります。

- **A**: 次の版の続報として、正しいことを書きます（例: 「〇〇市の新しい橋の開通は 12月ではなく 1月」と分かったら、次の版の続報で正し、経緯にも残します）。その出来事が次の版の20本に入る時だけ使えます。次の版の一覧に必ず出るので、読み終えた話題の誤りでも目に入ります。
- **B（おすすめ）**: 元の話題に「訂正」の短い記録（300字まで）を足し、アプリがその話題の上に「訂正: …」と出します。次の版の20本を使わずに済み、小さな誤りにも使えます。大きな続きがある時は、A の続報も使います。あなたが誤りに気づいた時に、Claude とのチャットから頼んで訂正を足す道も作れます（段階3）。訂正の記録は、元の話題と一緒に30日で消えます（保存した話題には、写して残します）。ただ、訂正は元の話題に付くので、読み終えた話題だと、前の版を開き直さない限り目に入りません（次の版の上で静かに知らせるかは、段階2で決めます）。
- **C**: 同じ枠の版をまるごと作り直して、差し替えます。誤りをその場で消せますが、使用量がもう1回分（試運転では約264万トークン）かかり、前に読んだ版と中身が変わります。
- どれでも、作れなかった版を後から作って出すことはできます（作れなかった印は、版と別の記録なので）。用語の辞書の誤りは、どれでも、新しい説明を足して直します。

### 3. 用語の説明が新しくなった時、前の話題の説明はどうするか

背景: 「いまの与党は〜」のように時期で中身が変わる語は、辞書に新しい説明を足します（5.8）。前に出た話題（30日以内の物と、保存した話題）の説明をどうするかです。

- **A（おすすめ）**: 前の話題は、その話題が出た時の説明のままにします（「2026年11月時点」と添えます）。その日の出来事は、その日の説明で読むほうが正確なためです。新しい話題からは新しい説明を出します。「知ってる」にしていた語は、新しい説明の話題でもう一度出ます。
- **B**: 前の話題でも、いちばん新しい説明に替えて出します（アプリも辞書を受け取るようにします。新しい端末の初めての受け取りが、1年で約 730回増えます）。

### 4. バックアップ（書き出し）を作るか

- **A（おすすめ）**: 段階1では作りません。保存した話題と「知ってる」はクラウドに無期限で残り、新しい端末にも届きます。版と話題は30日で消えるので、書き出す物があまりありません。要る時は後から足せます（覚え方は変わりません）。
- **B**: 段階1で、保存した話題と「知ってる」を1つのファイルに書き出す・読み込む機能を作ります（Diary Studio の設定のバックアップと同じような物）。
