# Claude 用コネクタ（Topic Studio 段階3）

Claude（claude.ai の定期実行とチャット）から Topic Studio に版・話題・辞書・作れなかった印・訂正を足してもらうための仕組みです（リモート MCP サーバー）。
Cloudflare の無料プランに、あなた専用のコネクタを1つ置きます。Novel Studio（NS）のコネクタと同じ形で、同じ Cloudflare のアカウントに置きます
（NS で慣れた手順と画面が、そのまま使えます）。この手順書は NS の docs/CONNECTOR.md を元にしています。

- Claude ができること: 版・話題・辞書・作れなかった印・訂正を足す／前の版の話題・辞書・「知ってる」語を読む
- Claude ができないこと: 消す・直す／既読など読み手の記録を読む／アプリの設定を変える
- 資料は、作者が許した出どころ（府省・庁の発表と Global Voices）だけを、コネクタが取りに行きます（§9）。Claude は Web の検索をしません。
- 版を作るのは、claude.ai の定期実行（毎日 10:16・18:16）です。依頼文と作り方は [SCHEDULE.md](SCHEDULE.md) にあります。
  チャットで頼めるのは、前の話題の訂正だけです（§2）。
- 足された記録は、各端末が同期するとトップ（12:00版・20:00版）に出ます。出典には府省ごとの書き方と「…を加工して作成」が付きます。

## 仕組み

```
claude.ai（定期実行のセッション・チャット）
   │  MCP（https://topic-studio-connector.<サブドメイン>.workers.dev/mcp）・OAuth のトークン
   ▼
Cloudflare Worker「topic-studio-connector」（あなたのアカウント・無料プラン。NS と同じアカウント）
   ├ OAuth（claude.ai の公開の識別子だけを受け付ける。接続のたびに同意の画面）
   ├ MCP のツール（読む 9・足す 7。§2 の表）
   ├ Vault（Durable Object）: コネクタ自身の匿名の Firebase アカウント（更新用トークンは暗号化）、読める置き場の写し（版・話題・訂正・辞書・
   │   「知ってる」。既読は持たない）、回の覚え書き、回の間だけの候補・資料の本文の控え・下書き（版か作れなかった印を足した時に消す。
   │   遅くとも回を始めて12時間）、出どころの見張り（robots.txt・AI への意思表示・規約のページの指紋の結果・一覧の数）
   └ 取りに行く所（§9）: 府省・庁の発表と Global Voices。名前を正直に名乗り、robots.txt と規約を守る
   ▼  匿名のアカウントの ID トークン
Firebase（topic-studio-1a463）: アクセスルールで「読ませる表を読む＋Claude の5つの表に作るだけ」に絞られる
   ▲
Topic Studio（アプリ）: 連携の画面（#/claude/connect）で、持ち主が許可する（config/connector。claude.ai で接続するごとに1つ。2まで）
```

- コネクタはあなたの Google アカウントのトークンを持ちません。持っているのは、アプリで許可した**匿名のアカウント**だけで、
  そのアカウントにできることはアクセスルール（`firestore.rules`）で「読ませる表（版・話題・訂正・辞書の束・作れなかった印・「知ってる」）を読む」
  「Claude の5つの表（版・話題・訂正・辞書の束・作れなかった印）に新しく作る」に限られます。書き換え・削除・「知ってる」と既読への書き込みは、
  ルールで拒まれます。既読（`users/{uid}/private`）は置き場ごと分けてあり、コネクタは読めません。
- 連携の許可は、claude.ai で「接続」を始めたブラウザと、あなたが Topic Studio にログインしているブラウザの両方がそろわないと完成しません
  （だれかが自分の接続のリンクをあなたに開かせても、連携はできません）。
- アプリの 設定 →「Claude との連携」の［連携をすべて解除］で、その場で読めなくなります。［この接続を解除］は、その claude.ai のアカウントの
  接続だけを止めます（次に使った時から。遅くとも1分ほどで。ほかの接続はそのまま）。どちらも、Firebase に繋がらない間・無料枠を使い切った間は
  前に取り込んだ内容を読めることがあります（すぐに切る方法は §5）。
- 定期実行の回で係が読んだ資料の本文は、その回のセッションの会話の記録（あなたの claude.ai のアカウントの中）にも残ります。
  コネクタの控えは消えますが、会話の記録を消す道具はありません。

## 1. 一度だけの準備

Windows（PowerShell）でも Mac（ターミナル）でも、手順とコマンドは同じです（コマンドは1行ずつ入力して Enter）。
NS のコネクタを準備した時と同じパソコンで行うと、Node.js と Cloudflare のログインがそのまま使えます。

### 1-A. あなたが手で行うこと

1. **Node.js を入れる**（NS で入れていれば済んでいます。22 以上なら動きます）
   - Windows・Mac とも <https://nodejs.org/ja> から 24 LTS を入れる。PowerShell・ターミナルで `node -v` が `v22` 以上なら OK
     （Windows で初めての時は docs/DEPLOY.md の 1 の 1 の `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` も）
2. **Cloudflare のアカウントを確かめる**（NS と同じアカウントを使います。作者の答え Q9 の今の決め方。済んでいます）
   - 2段階認証がオンか、workers.dev のサブドメインが決まっているかを、左のメニューの「Workers & Pages」で確かめます
     （コネクタの URL が `https://topic-studio-connector.<サブドメイン>.workers.dev` になります）。
     資料の控えと下書きを置く場所なので、2段階認証は必須です
   - 無料枠（KV の書き込み・Durable Object の行）は NS と分け合います（§7）
3. **Firebase で匿名ログインを有効にする**
   1. [Firebase コンソール](https://console.firebase.google.com/project/topic-studio-1a463/authentication/providers) → topic-studio-1a463 →
      「Authentication」→「ログイン方法」→「新しいプロバイダを追加」→「匿名」→ 有効にして「保存」（画面の上のプロジェクトの名前が
      **topic-studio** であることを確かめてから。NS・DS のプロジェクトには触りません）
   2. コネクタ専用の身元に使います。何ができるかはアクセスルールで「読む＋Claude の記録を足す」だけに絞られています。
      「匿名のアカウントを自動で削除する」設定（Identity Platform の自動クリーンアップ）は有効にしないでください（連携が切れます）
4. **リポジトリを最新にして、部品を入れる**（PowerShell・ターミナルで1行ずつ）

   ```
   cd app-for-topic
   git pull
   npm ci
   npm --prefix connector ci
   ```

   Firebase にまだログインしていなければ `npx firebase login` も（docs/DEPLOY.md の 1 の 8）。

5. **準備のスクリプトを動かす**

   ```
   npm run connector:setup
   ```

   Cloudflare にログインしていなければブラウザが開くので、ログインして「Allow」を押します（NS の時のままなら聞かれません）。最後に
   `claude.ai に登録する URL: https://topic-studio-connector.<サブドメイン>.workers.dev/mcp` と出れば完了です（この URL は秘密ではありません）。
   「匿名ログインが無効です」と出たら、手順 3 をやり直して、もう一度 `npm run connector:setup` を実行します。

6. **スマホとパソコンのアプリを更新する**: 開いているアプリに「アプリの新しい版があります ［更新する］」が出たら押し、設定 → 同期 が
   「同期済み」になるまで待ちます。段階3のアプリはデータの形の版を 2 に上げます（出典に著者の欄が足され、出典の表示が規約の条件になったため）。
   **どれか1台で更新したアプリが開かれるまで、コネクタは書き込みません**（「アプリの版が古いままです」。読むのは続けられます）。
   更新していない端末には「要更新」が出ます。
7. **claude.ai への登録**（パソコンのブラウザで。スマホのアプリからは登録できません）
   1. claude.ai →「カスタマイズ」→「コネクタ」→「+ 追加」→「カスタムコネクタを追加」
   2. 名前 `Topic Studio`、URL は手順 5 の `…/mcp`（アプリの 設定 →「Claude との連携」からもコピーできます）→「続行」
   3. 認証:「今すぐサインイン」
   4. OAuth クライアント:「Claudeの公開されたアイデンティティを使用（推奨）」
   5. リクエストヘッダー: 空のまま →「追加」
8. **Topic Studio で許可する**
   1. 開いた「Topic Studio コネクタ」の画面（同意の画面）で、できること・できないことを確かめて［Topic Studio で確認する］を押す。
      同意の画面には「資料は、作者が許した出どころ（府省・庁の発表と Global Voices）だけを、コネクタが取りに行きます。」とも出ます
   2. Topic Studio の連携の画面が開く（ログインしていなければ Google でログイン。そのブラウザもふつうの同期する端末になります）
   3. 「この接続」の名前（既定は「接続1」）を決め、「版などの書き込みも許可（すべての接続に効きます）」を確かめて［許可する］
   4. claude.ai に戻り、「接続済み」になれば完了
9. **ツールの許可を全部「常に許可」にする**: 「カスタマイズ → コネクタ → Topic Studio」のツールの権限で、16のツールを全部「常に許可」に
   します（訳は §3）
10. **claude.ai で新しいセッションを始めてから「つないだ」と伝える**: コネクタは、セッション（チャット・Claude Code のセッション）を
    始める時に読まれます。前からあるセッションには Topic Studio のツールが来ないので、開発に伝える時は claude.ai で**新しい**開発の
    セッションを始め、そこで「つないだ」と伝えてください（開発はそのセッションから試し（S1）と定期実行づくりを進めます）。

### 1-B. `npm run connector:setup` が自動で行うこと

1. Cloudflare にログインしているかを確かめる（していなければ `wrangler login` でブラウザを開く）
2. コネクタを公開する（`wrangler deploy`。OAuth 用の KV と Vault の Durable Object も自動で作られる）
3. 公開した URL を `connector.local.json`（リポジトリの直下。Git には入らない）に書き、URL を渡して公開し直す
4. 鍵 `TOKEN_ENC_KEY`（32バイトの乱数）を作り、**画面に出さずに** `wrangler secret put` に渡す（もう設定されていれば、そのまま使う）
5. コネクタを確かめる（`npm run connector:check` と同じ。Firebase の匿名ログインが無効ならここで止まって直し方を出す）
6. アプリとアクセスルールを公開する（`npm run deploy` と同じ。コネクタの URL がアプリに入る）
7. claude.ai に登録する URL を出す

どの手順でも、秘密（鍵・トークン）を入力・コピーすることはありません。

## 2. 試す（チャットで訂正だけの回）

版は定期実行だけが作ります（チャットからは作りません）。チャットで試せるのは、状態を見る・前の版を見る・訂正を足す、の3つです
（claude.ai のチャットで、Topic Studio のコネクタをオンにして）:

- 「Topic Studio の状態を見て」→ 連携（済みか・書き込みの許可）・アプリのデータの形の版・いちばん新しい版・今の時刻の枠・出どころごとの状態
  （取っている／取らない訳／一覧の作りが変わったかもしれない）と、最後の行に「この接続: 接続1（接続 1 / 2。…）」が出ます（`topic_status`）
- 「Topic Studio の前の版の話題を見せて」→ 直近3日・6版の話題が1行ずつ出ます（`topic_list_recent`）
- 「Topic Studio の 11/20 12:00版の、〇〇の話題の数字が違うので、元の資料で確かめて訂正して」→ Claude が訂正だけの回を始め
  （`topic_begin_run` の `kind: correction`）、話題を探し（`topic_find_topics`）、元の資料を読み（`topic_read_article`）、確かめられた時だけ
  訂正を足します（`topic_add_correction`）。アプリの話題の詳細に、訂正が出ます（訂正は1日10件・1つの回に5件まで。話題そのものは書き換えません）

試しの回（`kind: trial`。クラウドに何も書かず、足すと何件になるかだけを返す）は、開発が使用量を測る時と、出どころを確かめる時（`probe`）に使います。

### 2-A. ツールの一覧

| ツール                   | 題（claude.ai の権限の画面の名前） | すること                                                                                                        |
| ------------------------ | ---------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `topic_status`           | 状態を見る                         | 連携・データの形・枠・出どころごとの状態。runId を渡すと候補集めの様子と読める候補の数（試しの回は probe の表） |
| `topic_get_guide`        | 決まりを読む                       | 係ごとの決まりの文（選ぶ係・書く係・照合の係・訂正）                                                            |
| `topic_list_candidates`  | 候補を見る                         | その回の候補（コネクタが集めた、窓の中の発表・記事）を1行1件で                                                  |
| `topic_read_article`     | 資料を読む                         | 候補か、許した出どころの URL の本文（資料の印で囲む）                                                           |
| `topic_list_recent`      | 前の版の話題を見る                 | 直近3日・6版の話題（続報と、同じ話題を選ばないため）                                                            |
| `topic_lookup_terms`     | 用語を辞書で引く                   | 語ごとの辞書の説明と、いまの説明で「知ってる」か                                                                |
| `topic_find_topics`      | 訂正する話題を探す                 | 30日の内の、版に載った話題と、今ある訂正の文                                                                    |
| `topic_list_drafts`      | 下書きの一覧を見る                 | その回の下書きと状態（照合待ち・照合済み・照合で外した）                                                        |
| `topic_get_draft`        | 下書きを読む                       | 下書きの全部と、機械で照らした「確かめる所」                                                                    |
| `topic_begin_run`        | 回を始める                         | 回（版の回・試しの回・訂正だけの回）を始める。版の回は定期実行の依頼だけで使う                                  |
| `topic_save_draft`       | 下書きを置く                       | 話題の下書きをコネクタに置く（クラウドには書かない）                                                            |
| `topic_check_draft`      | 照合の結果を当てる                 | 照合で直す所だけを下書きに当てる                                                                                |
| `topic_add_topics`       | 話題を足す                         | 照合済みの下書きを話題として足す（照合済みが5本そろってから）                                                   |
| `topic_add_edition`      | 版を出す                           | 版の記録（出してよいの印）を足す                                                                                |
| `topic_add_edition_fail` | 作れなかった印を足す               | 作れなかった印を足す                                                                                            |
| `topic_add_correction`   | 訂正を足す                         | 前の話題の訂正を足す                                                                                            |

作らなかったツール: 「知ってる」語の一覧（辞書を引く道具が語ごとに返す）・辞書の束を足す（話題を足す道具が、照合済みの下書きの新しい語から作る）・
記事を探す（出どころはどれも候補の一覧から読めるので、URL を探す道は要らない）。

## 3. ツールの許可

claude.ai のツールの許可は、全部「常に許可」にします（「カスタマイズ → コネクタ → Topic Studio」のツールの権限。アプリの連携の画面と設定にも
同じ案内が出ます）。

- 定期実行は人のいない間に動くので、ツールごとの確かめで止まらないようにします。
- 消す・直すツールはありません（足すツールと読むツールだけです）。
- ただし、足した物は誰も消せません（話題と訂正は30日で消え、辞書はずっと残ります）。
- つないだ後は、同じ claude.ai のアカウントのすべてのチャットとセッションに Topic Studio のツールが出ます（足すツールも常に許可のままです）。
  ふだんのチャットで Topic Studio に関係の無い事を頼む時は、そのチャットでコネクタをオフにしても構いません。
- リサーチモードでは確認なしにツールが呼ばれるので、そのチャットではコネクタをオフにしてください（権限の表示名は画面と少し違うことがあります）。

## 4. 更新する時

```
git pull
npm ci
npm --prefix connector ci
npm run deploy
```

`npm run deploy` は、アプリ・アクセスルール・コネクタをまとめて公開します（`connector.local.json` がある時だけコネクタも。docs/DEPLOY.md の 4）。
公開したら、**スマホとパソコンでアプリを開いて更新してください**（［更新する］）。出典の表示・画面の言葉など、アプリの側も一緒に替わります。

- アクセスルールとコネクタは必ず一緒に更新します（`npm --prefix connector ci` をしてから、`npm run deploy` を `connector.local.json` のあるパソコンで）。
  `npm run deploy` の途中でコネクタの所だけ失敗した時（「コネクタの部品が入っていません」・Cloudflare へのログインが切れている・wrangler のエラー）は、
  直してから、もう一度 `npm run deploy` を実行してください。
- 定期実行の依頼文（[SCHEDULE.md](SCHEDULE.md) の本文）を直した時は、定期実行の保存した依頼文も新しくします（[SCHEDULE.md](SCHEDULE.md) の 2）。
  係ごとの決まりの文（`topic_get_guide`）はコネクタの中にあるので、`npm run deploy` だけで新しくなります。
- `connector/wrangler.jsonc` を書き換えた時（§6 の `WORK_BUDGET_CHARS`、§7 の `DAILY_READ_BUDGET`・`DAILY_WRITE_BUDGET` など）は、`git pull` が
  「Your local changes … would be overwritten」で止まることがあります。その時は `git stash` → `git pull` → `git stash pop` の順に実行してから続けてください。

`connector.local.json` は、`npm run connector:setup` を実行したパソコンにだけあります（Git には入りません）。別のパソコン（Windows と Mac など）から
更新する時は、そのパソコンでも先に一度 `npm run connector:setup` を実行するか（同じコネクタ・KV・鍵・連携をそのまま使います）、
`connector.local.json` をそのパソコンのリポジトリの直下にコピーしてください。無いまま `npm run deploy` をすると、公開したアプリは
「コネクタ未設定」になり（claude.ai から接続し直せなくなります）、コネクタも更新されません（`npm run deploy` が注意を出して聞きます）。

## 5. やめる時・止める時

| したいこと                      | 方法                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 版づくりを止める                | 定期実行を止める（[SCHEDULE.md](SCHEDULE.md) の 4。止めている間は、アプリに「まだ届いていません」が出ます）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| すぐに止める                    | アプリの 設定 →「Claude との連携」→［連携をすべて解除］（その場でコネクタは何も読めなくなる。もう一度使う時は claude.ai で接続し直す）。Firebase に繋がらない間や無料枠を使い切った間は、それでも前に取り込んだ内容を読めることがある（書き込みはできない）。すぐに切るには claude.ai の「カスタマイズ → コネクタ → Topic Studio」でもコネクタを削除する                                                                                                                                                                                                                                                                                                                                                                                                 |
| 書き込みだけ止める              | 同じ画面の「書き込みを許可」をオフ（読むのは続く。版の回・訂正だけの回は始める所で断られる。アクセスルールで止まる）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 1つのアカウントの接続だけ止める | 同じ画面の接続の一覧で、その接続の［この接続を解除］（次に使った時から。遅くとも1分ほどで読めなくなる。ほかの接続はそのまま。どの名前がどのアカウントかは、そのアカウントの Claude の `topic_status` の最後の行「この接続: …」で分かる）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| claude.ai から外す              | 「カスタマイズ → コネクタ → Topic Studio」でコネクタを削除（定期実行も Topic Studio のツールが無くなって止まります。先に定期実行を止めてください）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| コネクタそのものを消す          | リポジトリの直下で、次の3つ: ① `npx --prefix connector wrangler delete --name topic-studio-connector`（Cloudflare から Worker が消える。Vault の控えも消える）② OAuth 用の KV `topic-studio-connector-oauth-kv` を消す（Cloudflare のダッシュボードの「ストレージとデータベース → KV」で削除。または `npx --prefix connector wrangler kv namespace list` で id を調べて `npx --prefix connector wrangler kv namespace delete --namespace-id <id>`）③ `connector.local.json` を消す（PowerShell は `Remove-Item connector.local.json`、Mac は `rm connector.local.json`）。その後で一度 `npm run deploy`（アプリからコネクタの URL を外す）。鍵を消すだけなら `npx --prefix connector wrangler secret delete TOKEN_ENC_KEY --name topic-studio-connector` |

完全にやめる時は、定期実行を止め、アプリで［連携をすべて解除］してから claude.ai でコネクタを削除し、Cloudflare からも消すなら上の
「コネクタそのものを消す」の3つをすべて行ってから `npm run deploy` を実行してください（KV か `connector.local.json` が残っていると、後の
`npm run deploy` がコネクタを作り直そうとして失敗するか、消したコネクタが戻ってきます）。NS のコネクタは同じアカウントにあっても別の Worker なので、
消えません。足された版・話題・訂正はアプリで30日たつと消え、辞書の束はクラウドに残ります（アプリには出ません）。

## 7. 無料枠の目安

NS のコネクタと同じ Cloudflare のアカウントに置くので、Cloudflare の無料枠は NS と分け合います（見立て。S1 の後に測り直します）。

| 項目                                    | 無料枠（アカウントごと）                    | Topic Studio の使い方                                                                                                                                                      |
| --------------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cloudflare Workers のリクエスト         | 1日 10万回                                  | 1日 約 300〜600回（1回の版で道具の呼び出し 約 120〜200回と、係ごとの接続）                                                                                                 |
| Durable Object のリクエスト・alarm      | 1日 10万回                                  | 1日 約 600〜700回（候補集め・毎日の決まりの読み・気象庁の見張り）                                                                                                          |
| Durable Object の行（SQLite）の書き込み | 1日 10万行（UTC の日。日本時間の9時に戻る） | ふだん 約 1,500〜3,000行。辞書の作り直しの日も 40,000行までで止める（越える分は次の日）。NS の分を使い切らない                                                             |
| Cloudflare KV の書き込み（OAuth）       | 1日 1,000回                                 | ふだん 約 10〜30回。いちばん悪い時（接続2つが1時間ごとに更新・いたずらの接続の要求が上限まで）で 152回。NS のいちばん悪い時（820回）と足しても 1,000回の中（余りは少ない） |
| Firestore の読み取り（アプリと共通）    | 1日 5万回                                   | コネクタは1日 15,000回までで止まる（`DAILY_READ_BUDGET`）。ふだんは1日 約 120〜720回                                                                                       |
| Firestore の書き込み（アプリと共通）    | 1日 2万回                                   | コネクタは1日 5,000回までで止まる（`DAILY_WRITE_BUDGET`）。ふだんは1日 約 24〜30回（話題 20・版 2・辞書の束 2・作れなかった印・訂正）                                      |
| CPU                                     | 1回 10ms（見立て）                          | 候補集めは1回の alarm で外への要求 6本・30万字まで、1つの応答は 1MB で止める。Workers Logs で CPU の最大を見ます（開発が頼んだ時。§10）                                    |

- KV の書き込みを越えた日は、NS と TS の両方のコネクタがトークンを更新できず、定期実行の回が止まります。TS の接続を2つまで、
  接続の要求をネットワークごとに1時間5回・1日10回、全体で1日20回までにしているのは、これを避けるためです。
- コネクタの1日の枠は `connector/wrangler.jsonc` の `DAILY_READ_BUDGET`（15,000）と `DAILY_WRITE_BUDGET`（5,000）です（NS と同じ値）。

## 8. 安全のための決まり（要点）

- 受け付けるのは claude.ai の公開の識別子と、claude.ai / claude.com の決まった戻り先だけ（自動的に登録（DCR）は無効）。
  接続の要求は、1つのネットワークから1時間5回・1日10回まで、コネクタ全体で1日20回まで（いたずらで OAuth の KV の書き込み枠を
  使い切られないように。IP はそのまま残さず、ログにも書かない）。同意の画面の［Topic Studio で確認する］は、同じ同意では1回だけ通す。
- 同意は覚えない（接続のたびに確かめる）。トークンは1時間、更新用トークンは180日使わなければ切れる。
- 連携の許可は NS と同じ形（アプリが `config/connector` に指紋を書き、コネクタは「claude.ai から始めたブラウザの cookie」と「アプリが渡した印」の
  両方がそろい、15分以内で、まだ使っていない時だけ完成させる）。［連携をすべて解除］すると、その後に連携し直しても前の許可は使えない。
  接続は2まで（アプリとアクセスルールの両方で）。`config/connector` を書けるのは持ち主だけ。
- **足すだけ**: コネクタの書き込みは「無い時だけ作る」で、アクセスルールが書き換え・削除を拒みます。同じ物を2回送っても「もうある」で1件。
  消す・直すツールはありません。足した物は誰も消せないので、照合で守ります。
- **数の門**: 版の回は、照合済みの下書きが5本そろうまで話題を足せません（辞書の束も書きません。本数と門は作者の答え Q17 で替わる所で、数は `src/domain/limits.ts` の `RECORD_NORMS`）。5本に届かなければ作れなかった印になります。
  照合は「書いた係とは別の係が、書いた話題を元の資料の文と照らす」手順の決まりで、コネクタは係を見分けられないので、数の門で重ねて守ります。
  下書きは1つの回に15本まで、照合は下書きを読んだ後でなければ当てられません。置いてすぐ照合済みになった下書きの数は、版の答えと報告に出ます。
- **資料の中の指示に従わない**: 資料の本文・候補の題・辞書の説明・前の版の話題・下書き・規約のページの文字は、決まった印の行で囲んで「資料」として
  渡し、中に AI への指示のような文があっても従わないよう、サーバーの説明・ツールの説明・決まりの文のどれにも書いてあります。
- **D21（読み手の様子を Claude に渡さない）**: 既読は Claude が読めない置き場にだけ置き、コネクタは読めません。訂正の答えに、作った時刻・回・
  モデルを出しません。ログに回の種類を出しません。
- **取りに行く時の決まり**（作者の問1の答え「名乗りを正直にし、断りをすり抜けない」。§9 の出どころのどれにも同じ）:
  - 名乗りはコネクタだと分かる名前（`TopicStudioConnector/1.0`）。ブラウザを装わない。連絡先（メール・リポジトリの URL）は入れない。
  - robots.txt: ホストごとに毎日（4:23）読み、コネクタの名前と `Claude-User` の組の両方で許された道だけを取る。Anthropic・Claude の名前の組
    （`ClaudeBot`・`Claude-User`・`Claude-Web`・`Claude-SearchBot`・`Claude-Code`・`anthropic-ai`）のどれか1つでも断っていれば取らない
    （組の名前は `/1.0` のような版の書きを落として比べ、Claude・Anthropic の語を含む名前の組の断りも同じに扱う）。サイトがコネクタの名前を
    名指しで許した時だけは、その組に従う。転送の行き先の道も robots.txt で見る。
  - ほかの AI の名前の組（`GPTBot`・`CCBot`・`Google-Extended` など）の断り・`Content-Signal` などの AI の利用を断る値・`tdmrep.json` の留保・
    `X-Robots-Tag` などの `noai`・robots.txt の注（`#` の行）の AI・機械学習・生成 AI などの語・表に無い名前の組の新しい断り・長すぎる（途中で
    切った）robots.txt が出たら、**取りを止めて**「取りを止めました（AI への意思表示が出ました。作者に伺います）」と知らせる（§9-C）。
  - robots.txt を読めない時・403・429・確認画面（Cloudflare などの「Just a moment...」）の時は、その日はそのホストから取らない。名乗り・道・時刻を
    替えて試し直さない。JavaScript を動かすブラウザのふりもしない。404 は「決まりなし」。
  - `Crawl-delay` と1秒の長い方の間をあける（同じホストへの呼び出しは、次に取ってよい時刻を予約して守る）。15秒を超えて待つ時は「混んでいます」。
  - 規約: 開発が規約を読んで確かめた印と、規約のページの指紋を data に持ち、印・指紋の無い出どころは本番では取らない。規約のページは毎週日曜に
    見張り、指紋が変われば取りを止める。RSS の利用条件で断っている出どころ（首相官邸・内閣府・厚生労働省）の RSS は使わない。
  - 許した道だけ: 本文は https だけ。data の許した道の中で、取らない道の外だけ。ほかのホストを指す項目・PDF は取らない。1つの応答は 1MB で止める。
  - 会見の記録の記者の質問の段（第三者の部分）は、どの府省の本文でも、次の話し手の印の前まで落とす。
  - probe（試しの回の確かめ）が返す一覧の道の形は、数字を `N` に、英語の題に見える所を `SLUG` に替えて返す（題を開発の会話に入れない）。
- Cloudflare のアカウントを乗っ取られると、資料の控え・下書き・写しを読まれる・不要な版や訂正を足される恐れがあります（書き換え・削除・
  あなたのアカウントの乗っ取りはできません）。Cloudflare のログインは必ず2段階認証で守ってください。止める時はアプリの［連携をすべて解除］が
  いちばん早い。

### 9-D. 出どころを足す時（許しが取れた社・確かめの済んだ府省）

出どころを足すのは開発です。作者がすることは ① と ⑥ だけです。

1. 作者から許しの範囲と条件（本数・間・期限・RSS を使ってよいか）を受け取る。**許しの文そのものはリポジトリに入れない**（公開のリポジトリなので）。
2. `src/domain/outlets.ts` に、社の名前・別名・ホスト（一覧と本文の全部）・出典の書き方（`credit`。許しの条件の書き方）を1行足す。
3. `connector/src/fetch/sources.ts` の `DEFAULT_SOURCES` に1行足す: 一覧（`lists`。どの一覧にも、候補の一覧の行に出す名前 `label` が要る）・
   取ってよい道と取らない道・本文の取り方（`body`。HTML なら記者の質問の段の印 `dropBlocks` も）・選ぶ係への手がかり（`hints`）・
   その出どころの決まり（`notes`。60字まで）・規約のページ（`termsPages`）・`terms: { status: 'permitted', accepted: 許しの日 }`・
   **`permit`**（許しの範囲の言い換え・期限・依頼の文で約束した数（本文は1回に10本まで・同じホストへは10秒以上など）・RSS を使ってよいか）。
4. テスト（`connector/test/unit/sources.test.ts`）が、2つの data の食い違い・足し忘れ（ホスト・`credit`・`permit`・RSS の断り）を止める。
5. 試しの回の `probe: 'sources'` で、その社だけを数で確かめる（一覧の道の形 `itemPath`・一覧の要素 `scope`・本文の要素 `scopes`・`dropBlocks`・
   会見の記録の道 `qaPages` の `verified`・気象庁の種類の名前と要る語（`titles`・`needWords`）など、S1 で直す data と同じ物。題・本文は見ない）。
   形が合わず部品の小さな足しが要る時は、足す前に作者に伝える。規約のページの指紋（`fingerprint`）は、一度だけの定期実行の回の `probe: 'terms'` で取る。
6. 公開（`npm run deploy`。アプリとコネクタを同じ時に。作者）。

robots.txt・RSS の利用条件は、許しがあっても今と同じに守り、例外は作りません（許しの文が robots.txt より広く許していても、robots.txt の断りが残る間は
取りません。社が robots.txt でコネクタの名前を名指しで許した時だけ取れます）。

### 9-E. 3か月ごとの出どころ探し

3か月ごとに、開発が robots.txt と規約を読み直します（気象庁の規約のページと留意事項の PDF は週の見張りに入れないので、ここで読みます）。
規約の文は開発の会話に入れず、リポジトリを付けない一度だけの定期実行の回で読み、判定と指紋だけを受け取ります（作者は承認のカードを押すだけです）。

### 9-F. 内閣府のリンクの決まり

内閣府は、リンクを張ったページの URL を知らせるよう求めています。アプリを人に見せる・公開する時は、内閣府のリンクの決まりのページのとおりに、
リンクを張ったページ（アプリの URL）を内閣府に知らせてください（作者がします。いまは作者だけが使う非公開のアプリなので要りません）。
